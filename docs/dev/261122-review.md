# cyllama review: security, architecture, optimization

- Date: 2026-11-22

- Commit: `e1a71a2` (v1.0.0a0), llama.cpp `b12359`, whisper.cpp `v1.9.5`, stable-diffusion.cpp `master-1094-3bad892`

- Scope: `src/cyllama/` (excluding the vendored jinja2 code), `scripts/`, `CMakeLists.txt`, `Makefile`, `pyproject.toml`, `.github/workflows/`

- Not covered: `tests/`, `docs/`, upstream C/C++ sources, published wheel contents

## Method and evidence levels

Six areas were read in full: llama bindings, whisper/SD bindings, servers and `api.py`, agents, RAG, build and packaging. Each finding carries one of three labels.

- **REPRODUCED**: triggered in a CPU-only subprocess on this machine. The exit code is given.

- **READ**: confirmed by reading every code path cited. Not executed.

- **INFERRED**: depends on third-party behaviour that was not available locally (psycopg, chromadb, qdrant, Windows loader, upstream defaults). Verify before acting.

`make test` was not run. No source file was changed.

## Summary

| Severity | Count | Main themes |
|-|-|-|
| High | 14 | Process aborts from Python input, ACP tool gating, data loss in pgvector, supply chain |
| Medium | 33 | Server robustness, lifetime gaps, contract enforcement, backend inconsistencies |
| Low | 12 | Validation gaps, CLI flags, dead code |

Three root causes account for most findings.

1. **The binding layer trusts its Python caller.** Six inputs were reproduced aborting or segfaulting the interpreter (H1, H4, H5, H6, H14, M7). No `.pxd` uses `except +`, so every C++ throw calls `std::terminate`.

2. **Each feature has several independent implementations.** Six sampler-chain builders, four generation loops, three tool-dispatch paths, three backend-option maps. H1, M2, M15 and L7 are all cases where one copy has a guard the others lack.

3. **A release wheel is not reproducible from the repo.** Four mutable upstream tags, an unpinned Vulkan SDK, and unpinned repair tools feed it (H12, M29, M31, M33).

Alternative framing: treat this as two products with different risk. The core (`LLM`, `complete`, `chat`, bindings) is the 1.0 commitment. The servers, ACP, workflow engine and four vector-store backends hold most of the open defects and could ship marked experimental. That shrinks the 1.0 blocking set to H1, H4-H7, H10 and H12-H14.

## High

### H1. A batch larger than `n_batch` aborts the process. Remotely reachable. REPRODUCED (exit 134)

`LlamaContext.decode` (`src/cyllama/llama/llama_cpp.pyx:3784`) passes the batch to `llama_decode` unchecked. Upstream asserts `GGML_ASSERT(n_tokens_all <= cparams.n_batch)` (`llama-context.cpp:2227`). A 42-token batch on a context with `n_batch=16` killed the interpreter.

Callers that decode a whole prompt in one batch:

- `src/cyllama/llama/server/python.py:291` (`ServerSlot.stream`, used by both servers). The only guard is `len(prompt_tokens) >= n_ctx`. With the `ServerConfig` defaults (`n_ctx=4096`, `n_batch=2048`) one request with a 2049-4095 token prompt kills the server. No API key is required by default. A 2 MB body holds about 500k tokens.

- `src/cyllama/agents/constrained.py:87`. `max_context_chars=16000` is roughly 4000 tokens; `DEFAULT_N_BATCH` is 2048.

- `src/cyllama/llama/cli.py:509`.

- `src/cyllama/api.py:1302`. The loop chunks by `config.n_batch`, but `_ensure_context` (`api.py:1051`) reuses a context created with a different `n_batch`. `LLM(path, n_batch=64)` followed by a call with `GenerationConfig(n_batch=512)` aborts.

Fix: raise `ValueError` in `decode` and `encode` when `batch.n_tokens > llama_n_batch(ctx)`. Chunk by the context's own `n_batch` in the four callers. The server `__main__` default (`--ctx-size 2048`) hides the bug; the library default does not.

### H2. ACP exposes `run_command`, `write_file`, `read_file` with no permission gate. READ

- `src/cyllama/agents/acp.py:287-302` registers the three tools on every inner agent.

- `acp.py:381` defines `_request_permission`. Nothing calls it.

- `acp.py:465` advertises `"permissions": True`.

- `acp.py:350` sends `terminal/create` with the model's command string.

Scenario: a file read through `read_file` contains `Action: run_command(command="...")`. The model emits it. The agent sends it to the editor with no `session/request_permission` round trip. Whether the editor prompts by itself is INFERRED.

Fix: call `_request_permission` before each of the three tools, deny by default on timeout, or stop advertising the capability.

### H3. ACP agent-to-editor requests can never receive a reply. READ

`JsonRpcServer.serve` (`src/cyllama/agents/jsonrpc.py:299-305`) reads and dispatches on one thread. The `session/prompt` handler runs on that thread (`jsonrpc.py:278`), then blocks in `event.wait` (`jsonrpc.py:243`) for a reply only that thread can read.

- `fs/read_text_file` and `fs/write_text_file` always time out after 30 s. The editor has already performed the write.

- `terminal/create` times out after 10 s. `terminal/release` is never sent.

- `session/cancel` is read only after the prompt handler returns.

H2 and H3 together mean the ACP tool path has not worked end to end. Fix: dispatch request handlers on a worker thread and keep the reader thread free.

### H4. Invalid GBNF grammar segfaults on the next `sample()`. REPRODUCED (exit 139)

`_chain_add` (`llama_cpp.pyx:4378-4386`) adds the link without a NULL check. `llama_sampler_init_grammar` returns NULL on a parse failure. `add_grammar(vocab, "root ::= (", "root")` followed by `sample()` crashed.

Reachable from `agents/constrained.py:136` with a caller-supplied grammar. Fix: raise `ValueError` when `link` is NULL in `_chain_add`.

### H5. C++ exceptions terminate the interpreter. REPRODUCED (exit 134)

No `cdef extern` block declares `except +`. `vocab.token_to_piece(10**7, special=True)` ended with `libc++abi: terminating due to uncaught exception of type std::out_of_range`.

Other triggers (READ):

- `get_text`, `get_score`, `get_attr`, `is_control`, `detokenize` with an out-of-range id (`llama_cpp.pyx:1947-1965`, `2210`). A model with no EOT token returns -1 from `token_eot()`.

- `LlamaSampler.accept` with a token the grammar rejects (`llama_cpp.pyx:4464`).

- `add_grammar_lazy_patterns` with an invalid regex (`llama_cpp.pyx:4725`).

- `fold` and `convert_less_than_thousand` in `tts_helpers.pxi:80,88`.

Fix: range-check token ids against `n_vocab` in the wrappers. Declare `except +` on the functions that can throw. Range checks cost one comparison; `except +` alone converts the abort to `RuntimeError` but adds a try block per call.

### H6. `SDImage.load_ppm` reads past the buffer on a truncated file. REPRODUCED (exit 139)

`src/cyllama/sd/stable_diffusion.pyx:797-810`: `f.read(w*h*3)` may return fewer bytes; `memcpy` copies `w*h*3` regardless. A file containing only `P6\n8192 8192\n255\n` crashed. A smaller declared size copies adjacent heap bytes into the image instead of crashing.

Reachable from `SDImage.load("x.ppm")` and the CLI flags `--init-img`, `--mask`, `--control-image`. Fix: compare `len(pixel_data)` to `size` and raise `ValueError`.

### H7. `set_ref_images` and `set_pm_id_images` use an unchecked cast. READ

`stable_diffusion.pyx:2328` and `2352`: `(<SDImage>images[i])._image`. Cython does not type-check `<T>obj`. Passing a numpy array, a PIL image or `None` reads an `sd_image_t` from unrelated object memory. Generation then dereferences a garbage pointer.

Fix: use `<SDImage?>`. Copy the list (`list(images)`) so a later `images.clear()` cannot free the backing objects.

### H8. `PgVectorStore.add` does not commit after any read. READ; psycopg semantics INFERRED

`src/cyllama/rag/stores/postgres.py:419` wraps inserts in `conn.transaction()`. The read methods (`is_source_indexed` at `:509`, `get_source_by_label` at `:520`, `search`, `__len__`) open an implicit transaction and never commit. psycopg 3 documents that `transaction()` inside an open transaction creates a savepoint and does not commit.

`RAG.add_documents` calls both read methods before `store.add` (`rag/rag.py:337-387`). Chunks stay uncommitted and `close()` rolls them back. `tests/test_rag_pgvector.py` calls `add()` on an idle connection, so it passes. psycopg is not installed here; run the `add_documents` path against a real server to confirm.

Fix: open owned connections with `autocommit=True`. `transaction()` then issues a real BEGIN/COMMIT.

### H9. `AsyncRAG` fails with its default store. REPRODUCED (principle)

`rag/store.py:225` calls `sqlite3.connect(db_path, timeout=10)` on the caller thread. Every `AsyncRAG` method runs in `asyncio.to_thread` (`rag/advanced.py:98-261`). sqlite3 raises `ProgrammingError: SQLite objects created in a thread can only be used in that same thread`. The stdlib behaviour was reproduced; the `AsyncRAG` path itself was not run.

`tests/test_rag_advanced.py:78` builds `AsyncRAG` around a mock. `AsyncRAG` takes no `store=` argument, so no workaround exists. Fix: `check_same_thread=False` plus the existing lock, or a dedicated single-thread executor.

### H10. Abandoned async streams keep generating on the shared context. READ

`AsyncLLM.stream` (`src/cyllama/api.py:2580-2588`) cancels `producer_task` when the consumer exits early. `asyncio.to_thread` workers cannot be cancelled; the thread continues to `max_tokens`. `LLM.cancel()` is never called. The `async with self._lock` then exits.

`AsyncLLM` calls `_generate` and `_generate_stream` directly, bypassing `_busy_lock`. The next call runs `kv_cache_clear` and `llama_decode` on the same context while the orphan thread is inside `llama_decode` with the GIL released. Early exit is routine: client disconnect, `break`, per-chunk `timeout`.

The same pattern exists at `agents/async_agent.py:222-227` and `375-380` (orphan keeps executing tools) and `rag/advanced.py:197-206`.

Fix: call `self._llm.cancel()` in the `finally` block and await the thread before releasing the lock. Route `AsyncLLM` through the public locked entry points.

### H11. Whisper CLI transcribes stereo WAV as mono. READ

`src/cyllama/whisper/cli.py:120-149` never reads `nchannels`. Interleaved left/right samples reach `ctx.full` as mono at twice the length. The transcript is wrong and no error is raised. Fix: downmix, or reject `nchannels != 1`.

### H12. Upstream sources are pinned to mutable tags and never verified. READ

`scripts/versions.toml:4-7` holds four tags. `scripts/manage.py:329-337` runs `git clone --depth 1 --branch <tag> --recurse-submodules`. No code compares `git rev-parse HEAD` to an expected commit. `do_check_vendor` checks headers for the three ggml projects, not the compiled `.cpp` files.

Scenario: an upstream tag is force-moved. The next release build compiles the new commit into every wheel. Nothing fails.

Fix: store the 40-character commit beside each tag and fail on mismatch. One comparison per dependency.

### H13. PyPI publishing: long-lived token, branch-pinned action, missing gates. READ

- `build-cibw-abi3.yml:500-503` and `build-gpu-wheels-abi3.yml:334-337` use `pypa/gh-action-pypi-publish@release/v1` with `secrets.PYPI_API_TOKEN`. No trusted publishing, no attestations.

- `build-gpu-wheels-abi3.yml:322` publishes when `collect` succeeds. The GitHub release job at `:245-252` also requires a tag ref, `link_mode == 'dynamic'` and a non-failed smoke test. The PyPI job requires none.

- `build-cibw-abi3.yml:488` is `if: inputs.publish_to_pypi` with no tag check.

Scenario: a dispatch with `link_mode=static` and publish ticked uploads static wheels. They share filenames with dynamic wheels. `skip-existing: true` then drops the correct wheels. PyPI files cannot be replaced.

Fix: copy the release job's conditions to both publish jobs. Move to trusted publishing (`id-token: write`) and pin the action by commit.

### H14. `LlamaBatch` constructor and embd mode write out of bounds. REPRODUCED (exit 139)

`LlamaBatch(n_tokens=4, embd=8, n_seq_max=1).add(1, 0, [0], True)` segfaulted: upstream leaves `token` NULL in embd mode and `add` writes through it (`llama_cpp.pyx:805`).

READ, same class:

- `n_tokens=-1` or `n_seq_max=0` reach `llama_batch_init` unchecked (`llama_cpp.pyx:728-736`).

- `close()` (`:744-748`) frees the arrays and leaves the pointers and capacity. Later `add` or `decode` uses freed memory. `return_batch_to_pool` accepts a closed batch.

Fix: validate constructor arguments, reject token writes in embd mode, zero `self.p` and `_n_tokens` in `close()`.

## Medium

### Servers

**M1. `PythonServer` serves one connection at a time with no socket timeout. READ.** `python.py:496` uses `HTTPServer`, not `ThreadingHTTPServer`. `n_parallel` slots are never used concurrently. A client that sends headers and no body blocks every other request, including `/health`, indefinitely. A streaming response blocks the server for its duration.

**M2. Both servers ignore the model's chat template. READ.** `_messages_to_prompt` (`python.py:469`, `embedded.pyx:485`) emits `System:/User:/Assistant:` text. Instruct models receive an untrained format. `LLM._apply_template` already implements the template path. `top_p` is parsed and never applied. The seed defaults to a fixed 1337, so identical prompts return identical text. `finish_reason` is always `"stop"`.

**M3. Request fields are not type-checked. READ.** A JSON array body, a string `max_tokens`, or a non-string `stop` entry returns 500. In streaming mode the failure arrives after the 200 status line. `process_and_generate` (`python.py:267`) catches every exception and returns an empty 200.

**M4. `EmbeddedServer.start` installs SIGINT and SIGTERM handlers unconditionally. READ.** `embedded.pyx:188-189`. It replaces the host application's handlers and never restores them. `signal.signal` raises `ValueError` off the main thread, after the model is loaded. `api.py:871` states that the library avoids touching signal handlers. Fix: install them in `__main__.py`.

**M5. `LlamaServer` leaks the API key and never searches `PATH`. READ.** `launcher.py:114` passes `--api-key` in argv; `:214` logs the full command at INFO. `Path("llama-server").exists()` (`:187-191`) tests the current directory; `Popen` then resolves the bare name through `PATH`. The documented "put one on `PATH`" works only if a same-named file exists in the working directory. Fix: `shutil.which`, pass the key by `LLAMA_API_KEY`, redact the log line.

## Architecture

### A1. No validation boundary between Python and C

H1, H4, H5, H6, H7, H14, M7, M8, M9 share one property: a Python value reaches C unchecked. The stated convention (`_check_open`, typed arguments) covers closed handles. It does not cover ranges, NULL results from constructors, or sibling-object state.

Proposal: one rule, enforced by test. No argument to a public `def` on a cdef class may abort the interpreter. `tests/test_native_guards.py` exists; extend it with one subprocess case per finding above. Each REPRODUCED finding here is a ready test.

Trade-off: range checks on per-token paths (`token_to_piece`) add one comparison per call. That is negligible next to a `llama_decode`.

### A2. Parallel implementations drift

## Optimization

Ranked by expected effect. None was measured in this review; the estimates are from reading.

### O1. Prompt-prefix reuse in `LLM`

`_ensure_context` clears the KV cache on every call (`api.py:1055`). `chat()` and the ReAct loop (`react.py:535`, append-only prompt) re-decode the full history each turn. Ten iterations at 4000 tokens decode 40000 prompt tokens where about 4000 are new.

Fix: keep the previous token list, find the common prefix, call `memory_seq_rm` from that position, decode the suffix. This is the largest available gain for agents and multi-turn chat. Risk: sampler state and the response cache must stay keyed on the full prompt.

### O2. Logits and embeddings as Python lists

`get_logits_ith`, `get_embeddings_ith` and three siblings (`llama_cpp.pyx:4081-4171`) allocate one `PyFloat` per element.

- `llama/decision.py:636-641` builds an `n_vocab` list to read a few label ids.

- `rag/embedder.py:459-461` pulls `n_tokens * n_embd` floats and mean-pools in a Python double loop (`:506-509`). About 200k float operations per 512-token chunk at 384 dimensions.

Fix: return a `float[::1]` memoryview or one `memcpy` into `array.array('f')`. Add an indexed accessor for the label case. Use `LLAMA_POOLING_TYPE_MEAN` in the context so llama.cpp pools.

### O3. Batched embedding and inserts

`embed_batch` (`embedder.py:386`) runs one `decode` per text with `n_seq_max=1`. The SQL stores insert one row per statement; on pgvector that is one round trip per chunk (`postgres.py:421`). Fix: multi-sequence batches; `executemany`.

### O4. Grammar sampler rebuilt per iteration

`_ensure_sampler_with_grammar` (`constrained.py:82`) re-parses the GBNF every agent iteration. `GrammarCache` stores only the text. `_tools_fingerprint` re-serialises all schemas each time. Fix: cache the fingerprint per agent; clone a parsed sampler.

### O5. Chat template compiled per call

`_apply_jinja_template` (`api.py:1660-1680`) builds an environment and compiles the template on every `chat()`. Fix: cache the compiled template on the `LLM` instance.

`apply_chat_template(messages, model_path)` and `get_chat_template(model_path)` load the full model to read one metadata string (`api.py:2087`, `2230`). `vocab_only` exists on `LlamaModelParams`.

### O6. GIL held during long native calls

Model load (`llama_cpp.pyx:2385`, `2451`, `2487`), context creation (`:3138`), state I/O, and all of mtmd init, tokenize and `eval_chunks` (`mtmd.pxi:505`, `792`, `879`) hold the GIL. Every other Python thread stalls for the duration. `decode` and `tokenize` already release it. Same for `whisper_cpp.pyx:1563`, `1596`, `1761`.

### O7. Per-pixel and per-sample Python loops

- `save_bmp` issues one `f.write` per pixel: 1,048,576 writes at 1024x1024 (`stable_diffusion.pyx:589-600`). `stbi_write_bmp` is declared at line 34 and unused.

- `whisper/cli.py:127-145` builds a Python list of floats before `array("f", ...)`. One hour at 16 kHz is 57.6M objects. `array('h').frombytes` avoids the list.

- `SDImage.load` copies stb's buffer and frees the original (`:941-947`); it could adopt it.

### O8. Redundant tokenization

`LLM._generate` tokenizes the prompt twice and re-tokenizes the output to count tokens (`api.py:1236`, `1247`). `_last_stream_stats` already has both counts. The servers do the same (`python.py:430-431`).

## Checked and found sound

- Chat templates render in `ImmutableSandboxedEnvironment` at all three sites. Vendored jinja2 is 3.1.6. The sandbox does not bound CPU or memory.

- Server auth: `hmac.compare_digest`, body-size precheck before the body is read, `SO_REUSEPORT` disabled, 500 bodies carry no detail, API key not accepted on the command line (`server/__main__.py`).

- No `eval`, `exec`, `pickle` or `yaml.load` outside vendored code. `shell=True` appears once (`agents/cli.py:167`), behind `--enable-shell`.

- SQL identifiers pass a regex validator; values are bound parameters; Postgres uses `sql.Identifier`.

- Session store paths are sanitised. `search_wikipedia` has a fixed host, timeout and size cap. `quarto_render` confines its write path.

- Buffer sizing and retry in `tokenize`, `token_to_bytes`, `detokenize`, `meta_val_str`, `chat_apply_template`, state save/load.

- `close()` and `__dealloc__` NULL the pointer in every resource class. Callbacks are `noexcept with gil` and catch `BaseException`. `nogil` blocks touch only C values.

- Patch application has a three-state check; a stale patch is fatal (`manage.py:1087-1099`).

- Workflows: no `pull_request_target`, top-level `permissions: contents: read`, no self-hosted runners, secrets only in dispatch jobs. Test model and CUDA redistributables are pinned by sha256.

- `Embedder`, `LLM`, `SDContext`, `WhisperContext`, `DecisionModel` hold a busy lock.

## Suggested order

1. **H1, H4, H5, H6, H7, H14, M7.** Small guards in the bindings. Each has a reproducer above. Add them to `tests/test_native_guards.py`.

2. **H12, H13.** Commit pins and publish-job conditions. Configuration only; do before the next release.

3. **H10.** Cancel and join on async early exit in three files.

4. **H2, H3.** Decide whether ACP ships in 1.0. If yes, fix dispatch threading first; the permission gate cannot be tested without it.

5. **H8, H9, H11.** One-line fixes each; H8 needs a real Postgres to confirm.

6. **A2** then **O1.** Consolidate the generation loop before adding prefix reuse, or the reuse logic becomes a fifth copy.

Open questions:

- Is the server meant for multi-user exposure? M1-M3 matter only if so. If it is a local development tool, state that in `SECURITY.md` and close them as documented limits.

- Should `LlamaBatch` embd mode exist? The wrapper cannot fill `p.embd`, so the mode is unusable. Removing it is smaller than fixing it.

- Does the 1.0 API promise cover `cyllama.llama.llama_cpp`? If yes, A1 is a compatibility commitment as well as a safety one.
